# M01 — 使用語音辨識前的供應商與隱私告知（2026-10-15）

## 問題

M01 預設流程以瀏覽器直接連至 Gemini Transcribe Live 進行雲端字幕辨識；MN4 token broker 供應短期憑證而不轉送音訊。既有首頁沒有在開始收音的主要操作區明確告知語音將送往外部服務，與 `docs/SAFETY.md`「Cloud STT: disclose clearly before use」要求不一致。

## 行為

- 在字幕區與「開始聆聽」之間提供一則**收音前即可看見**的文字，與開始按鈕的 `aria-describedby` 連結。沒有額外確認步驟、不要求另一個許可、不新增儲存。
- 預設 Gemini：明確標示音訊會傳送給 Google Gemini 進行雲端辨識。
- `?stt=browser`：標示辨識由瀏覽器提供，**可能使用雲端**，不誤稱一定是離線。
- `?stt=google`：標示音訊經語音代理送往 Google Cloud。
- 其他未知選項：以可能送往外部服務的保守提示取代保證本機處理。以上均提醒使用者先告知對話者。
- 告知文字在一般與專注閱讀模式均可見，不會隱藏在研究資訊區。
- 首頁改為「辨識不清楚時，再把手機移近說話者」，不再暗示必須將手機預先放在談話者附近；仍可不使用耳機直接閱讀字幕。

## 邊界

- 此改動**不是取得對話者同意的程式機制**；使用者仍需自行注意場景與所在地隱私規範。
- HearLens 前端既有模式不主動錄音存檔，轉錄文字目前主要存放於分頁記憶體；**本次沒有審核或承諾 Google／瀏覽器供應商／代理後端的保存與資料使用政策**。
- 目前的 token broker 不代表外部服務無法處理音訊；雲端 STT 的連線與資料流不因此變動。
- 沒有改 STT API、實際收音音訊、輸出路由、DSP、M03 聽力圖或 M04 安全封鎖。

## CI / 驗收

- Node 單元測試覆蓋 Gemini、Browser STT、Google Cloud 以及未知供應商的文案，驗證告知在開始按鈕之前出現並與輔助閱讀描述關聯。
- Playwright Chromium 在一般及專注閱讀模式、不同 STT query 下驗證文案和可見性，**不啟動麥克風，也不對外送音訊**。
- 本次不進行已完成的距離／增益／藍牙被動實驗；手機端字級與可讀性後續由使用者自行驗收。
